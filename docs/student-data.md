## 取得方法と利用条件

公式告知の募集・イベント・実装情報から短い事実項目を拾い、本文または見出しで名称と衣装を照合した。候補のうち、学校や列車の名前、同一生徒の誤表記などは省いた。各追加行に一次資料の告知IDを記録し、画面から参照できるようにした。名称・初期の星などの事実項目のみを保存し、告知本文、ゲームの紹介文、画像、ロゴ、抽出データを再配布する構成は採用していない。

既存のコミュニティ DB をまとめて取り込む方法は、元データの再配布条件を今回確認できなかったため採用しなかった。利用者が適法に用意したデータを私用インスタンスへ取り込む方式は、個別資料の権利・入力検証と配布用マスタとの分離が必要になる。既存の公式告知だけで照合可能な範囲を大幅に増やせたため、今回の拡充は公開リポジトリで確認できる一次資料と差分マイグレーションを選んだ。個人の所持・育成・編成は別テーブルに置く。

本アプリは個人向け・非営利の非公式ファンツール。公式の二次創作ガイドラインでは個人の二次創作は定義された非営利用途に限られる。作品とキャラクターの権利は各権利者に帰属する。運営移管の告知が出ているため、移管後の告知の掲載先とガイドラインを、新しい確認分から再確認する。 [二次創作ガイドライン](https://bluearchive.jp/fankit/guidelines) · [運営権移管の公式告知](https://bluearchive.jp/news/newsJump/703)

## 更新手順

1. 日本版の公式告知一覧で前回の確認日からの募集・メンテナンス・イベントを確認する。取得した一覧の件数・日付と、既存マスタとの差分を記録する。生徒の実装・受け入れを確認できる告知のIDと、公式の表示名を控える。
2. `catalog/` に、次のマイグレーション番号を接頭辞とした JSON を追加する。既存の `catalog/0005_catalog_2026_11_26.json` と同じ形式を使う。新規IDは `jp-` と、名称を NFKC 正規化して UTF-8 で SHA-256 にかけた結果の先頭16桁を連結する。採番済みのIDを維持し、通常版は衣装表記なしで入力する。初期の星や学園を確認できない項目は省略する。日本版掲載先が変わった場合は、出典リンクの保存形式も追加移行で更新する。
3. 確認済み JSON から同名の SQL を生成し、CI と同じ `npm run catalog:check`、`npm test`、ローカルのマイグレーション適用と再適用を実行する。既存行の修正は生徒IDを維持した別の SQL を追加する。
4. [リリース手順](deploy.md)に従ってプレビュー、新本番の順に適用し、D1 の件数を確認する。

```sh
node scripts/catalog-migration.mjs catalog/0006_catalog_YYYY_MM_DD.json > migrations/0006_catalog_YYYY_MM_DD.sql
npm run catalog:check
```

アプリはローカルの D1 だけで検索する。公式サイトの更新を読んだだけではマスタを書き換えない。
